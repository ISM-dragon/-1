# Media runtime

The private Gateway owns probing, normalization, extraction, rendering, and artifact validation. Android owns selection, upload, preview, lightweight edit intent, and download of server-produced media.

## Responsibilities

| Operation | Owner | Required behavior |
|---|---|---|
| Probe/validate | Gateway + ffprobe | Confirm readable container, video stream, duration, and supported input. |
| Audio extraction | Python/FFmpeg | Produce the normalized audio required by ASR and event detection. |
| Frame extraction | Python/FFmpeg/OpenCV | Supply candidate, scoring, and camera analysis frames. |
| CFR/transcoding | Python/FFmpeg | Normalize inputs that require constant frame rate or compatible codecs. |
| Camera/render | Python renderer | Apply camera trajectory, 9:16 output, captions, audio normalization, and artifact checks. |
| Cleanup | Gateway storage layer | Remove abandoned upload parts and failed temporary artifacts without deleting active jobs. |

## Stable media errors

`MEDIA_INVALID` means the source is unreadable or lacks a video stream. `UNSUPPORTED_FORMAT` means the source is readable but not accepted. `FFMPEG_MISSING` means the host lacks required binaries or filters. `FFMPEG_FAILED` means an invocation failed. `INSUFFICIENT_DISK` means the configured free-space threshold was exceeded. These codes are surfaced through the Gateway contract.

## Artifact rules

A result is published only after the renderer exits successfully, the expected output exists within the authorized job directory, and a final probe confirms a valid video stream, duration, and expected media metadata. Media URLs are generated by the Gateway; clients never construct filesystem paths.
