# ISM API Contract

**Base path:** `/v1`
**API version:** `1`
**Transport:** HTTPS in production, JSON for resources, multipart/raw stream for media upload.

## Conventions

Every private request accepts `Authorization: Bearer <gateway-session-token>`. The Gateway may also accept a request-supplied `X-Request-ID`; otherwise it generates one. Responses expose `request_id` and, where applicable, `correlation_id` and `job_id`. Timestamps are ISO-8601 UTC strings. IDs are opaque strings and must not be generated by clients for server-owned resources unless the endpoint explicitly accepts an idempotency key.

Errors use this shape:

```json
{
  "error": {
    "code": "PROCESSING_NOT_READY",
    "message": "The processing service is not ready.",
    "request_id": "req_...",
    "retryable": true
  }
}
```

## Session and diagnostics

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Public liveness/readiness summary. |
| GET | `/v1/auth/session` | Returns authenticated session status and API/product versions. |
| GET | `/v1/processing/capabilities` | Reports actual Gateway, pipeline, FFmpeg, storage, and AI readiness. |
| GET/POST | `/v1/diagnostics/pipeline` | Runs a bounded pipeline readiness check. |
| GET/POST | `/v1/diagnostics/gemini` | Reports provider configuration and, when requested, capability reachability. |
| GET | `/v1/diagnostics/workers` | Reports worker status without secrets. |

## Sources and processing

The Android canonical path creates a resumable upload with `POST /v1/sources/uploads`, sends `PUT /v1/sources/uploads/{upload_id}` chunks using `X-Upload-Offset` and `Content-Range`, and finalizes with `POST /v1/sources/uploads/{upload_id}/complete`. The legacy `POST /v1/sources/upload` remains only for compatibility clients. After upload completion, `POST /v1/processing/jobs` accepts:

```json
{
  "source": "https://gateway.example/v1/sources/jobs/upl_x/media/source.mp4",
  "llm": "gemini",
  "captions": "classic",
  "mode": "balanced",
  "idempotency_key": "client-generated-stable-key"
}
```

`GET /v1/processing/jobs/{id}` returns the durable job, current stage, progress, retry count, recoverability, error code, artifact manifest, and transition history. Control routes are:

| Method | Path | Semantics |
|---|---|---|
| POST | `/v1/processing/jobs/{id}/cancel` | Persist cancellation and interrupt active execution where possible. |
| POST | `/v1/processing/jobs/{id}/retry` | Requeue a recoverable failed job with bounded retry metadata. |
| POST | `/v1/processing/jobs/{id}/resume` | Requeue an interrupted job from its latest pipeline checkpoint. |

The canonical state vocabulary is `QUEUED`, `PREPARING`, `DOWNLOADING`, `INGESTING`, `TRANSCRIBING`, `DIARIZING`, `ANALYZING`, `CANDIDATES_READY`, `SCORING`, `EDITING`, `RENDERING`, `FINALIZING`, `COMPLETED`, `FAILED`, `CANCELLED`, `RETRY_WAIT`, and `INTERRUPTED`. Legacy clients may continue to receive `queued`, `running`, `done`, and `failed` in the compatibility `status` field while consuming the canonical `state` field.

## AI providers

`GET/POST/PATCH/DELETE /v1/ai/providers` manages provider metadata. `GET /v1/ai/models` lists model capabilities. Provider credentials are write-only and are never returned. Health responses distinguish `not_configured`, `degraded`, `ready`, `quota`, `auth_failed`, `timeout`, and `network_error`.

## Social accounts and OAuth

| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/social/accounts` | Lists redacted account state and capabilities. |
| POST | `/v1/social/{platform}/connect` | Starts a provider OAuth flow or returns a clearly labelled development flow. |
| GET | `/v1/social/{platform}/callback` | Validates state/nonce and completes the OAuth exchange. |
| POST | `/v1/social/{platform}/disconnect` | Revokes/removes Gateway-owned credentials. |
| GET | `/v1/social/{platform}/status` | Returns real account and capability status. |

Legacy `/v1/accounts`, `/v1/social/oauth/{platform}/start`, and `/v1/social/schedule` routes remain during migration.

## Publishing and analytics

`POST /v1/publishing/jobs` creates or reuses an idempotent publishing job after media, account, token, capability, quota, and schedule validation. `GET /v1/publishing/jobs/{id}` returns status, provider post ID, permalink, attempts, next retry time, and error category. Control routes are `/cancel` and `/retry`. `GET /v1/analytics` returns provider-backed metrics; unavailable values remain `null`. The existing `/v1/analytics/summary` and snapshot route remain compatible.

## Version and identity

The canonical product identity is `ISM`. The API version is `1`. Client builds must expose the same product name and compatible version metadata. Android namespace migration is intentionally separate from the API contract so existing installs can be preserved.
